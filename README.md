# Catch You Steadily：我会稳稳接住你

这是一个将中文 ChatGPT 经典“心理咨询/疗愈式”口癖在 Minecraft 中按字面物理实现的梗向模组（Meme Mod）。

在日常对话中，无论用户遇到何种突发状况或倾诉焦虑，AI 助手总喜欢预设用户的挫败心理，用极其温柔、过度共情且笃定的硅基客服腔调安慰用户，并伴随着那句经典的口头承诺：“我就在这里：不躲、不藏、不绕、不逃，我会稳稳地接住你。”

本模组将这句充满既视感的口头禅字面物理化：当你在游戏中失足下坠时，游戏判定系统不再只是计算重力，而是让地面附近的牛、羊、僵尸等原版生物放下手头活动，向着你的预测落点狂奔而来，尝试在落地瞬间用身体充当肉垫将你接住。

---

## 经典场景重现：当重力事故遇上硅基疗愈

> **玩家**：救命！我在两百格高空失足跌落了，底下全是没有水的硬石头，还有三秒就要摔死了！
>
> **GPT 助手**：
>
> 请先深呼吸。我非常理解你此刻面对重力加速度时的无助与失控感，你不用一个人硬撑。
>
> 请记住：**你不是在走向死亡，而是身体正在经历一次与大地的重新连接**。这不是一次失足，而是你在探索世界时勇敢迈出的又一步。
>
> 我在这里给你几点建议：
> 1. 放松手指，不必拼命敲击键盘；
> 2. 闭上双眼，倾听风穿过方块的声音；
> 3. 相信地面上正在奔跑的生命。
>
> 我就站在你的世界里：不躲、不藏、不绕、不逃。**别担心，我会稳稳地接住你。**
>
> 如果你需要，我还可以为你生成一份降落情绪复盘指南。随时告诉我，我一直都在。
>
> **地面上的原版僵尸与奶牛**：（收到寻路目标，中断日常游荡，顶着方块阻碍全速冲向落点充当肉垫）

## 游戏机制与物理限制

戏仿对话中的口癖属于艺术夸张与情绪抚慰，游戏内部的物理与生物寻路则遵循冷酷的客观法则：

- **生物赶路受物理规律制约**：生物依赖原生寻路与自身移动速度奔跑，无法跨越深坑、悬崖、高墙或栅栏。如果下落高度过低导致滞空时间不足，或者预测落点周围没有可用生物，生物很可能无法及时赶到。模组绝不提供虚空瞬移、隔空吸附或穿墙救人。
- **触发条件**：只要玩家处于下落状态且前向模拟预测落点为实体方块、预计会承受摔落伤害，救援逻辑便会启动，不要求达到致命伤害门槛。若预测落入深水等免伤介质，系统将保持静默。
- **摔落结算**：只有当玩家在下落时机与赶到的生物发生碰撞重叠，并成功建立原版骑乘关系时，本次累积的摔落距离才会被瞬间清零。
- **着陆后无持续免伤**：成功骑乘仅化解本次落地冲击。如果挺身而出接住你的是僵尸或苦力怕，在着陆解除骑乘之后，它们仍会按原版逻辑对你发动攻击，模组不提供任何无敌护盾或持续免伤。
- **骑乘与操控**：默认在平稳着陆后自动解除骑乘；若在配置文件中开启 `keep-riding`，玩家在着陆后将保持坐在生物背上的状态，但这绝不会赋予玩家操纵生物移动、转向或飞行的能力。
- **生物调度与仇恨**：默认允许敌对生物参与救援，可在配置中排除；救援仅向生物的行为选择器注入临时移动目标，不会修改生物原本的攻击仇恨。
- **纯服务端实现**：不包含任何新客户端界面（GUI）或额外渲染。

## 平台支持与独立分包

本项目并非全版本通用的单一 JAR 文件，而是针对不同加载器与版本分别提供独立分包：

- **Forge**：`1.7.10` / `1.12.2` / `1.20.1`
- **Fabric**：`1.20.1` / `1.21.1`（专服专用，必须安装对应版本的 Fabric API）
- **NeoForge**：`1.21.1`

各版本独立构建，互不通用。

---

## 安装与运行须知

- **服务端部署**：请将对应版本的 JAR 文件放入专有服务端（Dedicated Server）的 `mods` 目录中。
- **Fabric 环境限制**：Fabric 分包元数据明确限定为服务端环境（`environment: server`，仅注册 `entrypoints.server`），单机集成服务器不会加载该模组，且必须前置 Fabric API。
- **单机支持说明**：Forge 与 NeoForge 版本的单机客户端运行与免客户端安装尚未进行全面验证，目前不承诺单机环境的可用性。

---

## 配置与构建

- **配置格式与生效规则**：Forge 1.7.10 与 1.12.2 使用 `.cfg` 格式；现代 Forge 与 NeoForge 使用 COMMON `.toml` 格式；Fabric 由模组自行读写 Gson `.json` 格式（非 Fabric 官方配置 API）。修改配置必须在停服状态下编辑，重启服务端后生效。
- **源码构建**：在仓库根目录执行 `./gradlew buildReleaseJars`，六个目标的构建产物会分别输出到各子模块的 `build/libs/` 目录下，构建脚本不会自动汇总到 `build/release`。
- **详细说明**：有关黑名单实体配置、搜寻半径参数及历史版本 JDK 构建要求，请参阅[配置与构建说明](common/README.md)。
